└───────────────────────────────────────────────────────────────────────────────┘

Open a NEW terminal (Terminal 8) and run:

    sudo ip netns exec ue$i ip route add default dev tun_srsue 2>/dev/null

# Test connectivity (all 3 UEs)
for i in 1 2 3; do
    echo "=== Testing UE$i ==="
    sudo ip netns exec ue$i ping -c 3 10.53.1.1
done

Expected: 0% packet loss for all 3 UEs

═══════════════════════════════════════════════════════════════════════════════
Part A: Solo Capacity Tests (verify each UE can reach ~15-20 Mbps alone)
═══════════════════════════════════════════════════════════════════════════════
cd ~/Desktop/oran-work
./run_traffic.sh solo_ue1 30 60M 0 0
./run_traffic.sh solo_ue2 30 0 60M 0
./run_traffic.sh solo_ue3 30 0 0 60M

After each run:
    python3 ~/Desktop/oran-work/metrics_summary.py ~/Desktop/oran-work/runs/solo_ueX/gnb.log 20

Record: delivered Mbps for each UE (should be ~15-20 Mbps)

═══════════════════════════════════════════════════════════════════════════════
Part B: Equal Load Ramp (find total cell capacity C)
═══════════════════════════════════════════════════════════════════════════════
./run_traffic.sh eq_05M 30 5M 5M 5M
./run_traffic.sh eq_10M 30 10M 10M 10M
./run_traffic.sh eq_15M 30 15M 15M 15M
./run_traffic.sh eq_20M 30 20M 20M 20M

After each run, check delivered throughput:
    tail runs/eq_20M/iperf_ue*.txt | grep receiver

Sum the three delivered rates → this is your CELL CAPACITY (C)

Look for the plateau where:
    - Total delivered stops increasing
    - cell_util approaches 0.9-1.0
    - time_x stays ≈ 1.0

Example: If total delivered = 30 Mbps → C = 30 Mbps

┌───────────────────────────────────────────────────────────────────────────────┐
│ STEP 6: Overload Runs (Create Starvation Data)                               │
└───────────────────────────────────────────────────────────────────────────────┘

Calculate overload rates (replace C with YOUR measured capacity):
    1.3 × C → split unequally (e.g., C=30 → 39M total → 18M / 12M / 9M)
    1.5 × C → split unequally (e.g., C=30 → 45M total → 21M / 14M / 10M)

Run 120-second overload tests:
    ./run_traffic.sh over_130 120 18M 12M 9M
    ./run_traffic.sh over_150 120 21M 14M 10M

Verify starvation occurred:
    python3 ~/Desktop/oran-work/metrics_summary.py ~/Desktop/oran-work/runs/over_150/gnb.log 30

Look for:
    - cell_util ≈ 0.9-1.0 throughout
    - time_x ≈ 1.0 (NOT dropping!)
    - Some intervals where delivered < 0.5 × offered (starvation!)

Check iperf logs:
    head -20 runs/over_150/iperf_ue1.txt

Each line shows: timestamp, delivered bytes in 0.25s
Starvation = delivered < (offered_rate × 0.25 / 8) bytes

┌───────────────────────────────────────────────────────────────────────────────┐
│ TROUBLESHOOTING                                                               │
└───────────────────────────────────────────────────────────────────────────────┘

Problem: UEs never attach after starting GNU Radio broker
Fix:     - Stop broker (click "Kill" in GRC)
         - Restart ALL 3 UEs (Ctrl+C in each terminal, then re-run srsue)
         - Click "Execute" in GRC again

Problem: One UE gets "Received RRC Release"
Fix:     - Check http://localhost:9999 → verify all 3 IMSIs exist
         - If missing, rebuild 5gc: docker compose up --build 5gc

Problem: time_x < 0.85 with 3 UEs
Fix:     VM cannot run 3 UEs in real time. Options:
         1. Close all other apps, give VM more CPU cores
         2. Reduce to 2 UEs only (acceptable for Day 4)
         3. Report to dataset team (may affect E6 experiment design)

Problem: iperf3 "server is busy"
Fix:     Each UE needs its own port (5201, 5202, 5203)
         Kill old servers: sudo killall iperf3
         Restart: for p in 5201 5202 5203; do iperf3 -s -p $p -D; done

Problem: "route add" says "File exists"
Fix:     Route already present (harmless), proceed

Problem: GNU Radio crash or "ZMQ bind error"
Fix:     - Kill all processes: sudo killall gnb srsue
         - Wait 60 seconds
         - Restart from Terminal 3 (gNB) onwards
